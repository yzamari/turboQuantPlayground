## Six on-device crashes diagnosed and fixed in one day

The session got long because P2.1c α had a *layered* set of issues; each
fix exposed the next. Captured here so the next person knows what to
expect when touching this path.

1. **`set_input_kq_mask` SIGSEGV** (carry-over from previous session).
   `kq_mask` was created via `ggml_set_input` but no graph node consumed
   it; allocator dropped its buffer; `set_input_kq_mask` faulted on a
   null buffer. **Fix:** switched `ggml_map_custom3(...)` → `ggml_custom_4d(...)`
   with `args = {q, k, v, kq_mask}` so kq_mask is a real op dependency.
2. **`q->type == GGML_TYPE_F32` SIGABRT.** Custom op asserted F32
   only; with Llama-3.2-1B the activations and cache are F16.
   **Fix:** accept either dtype, upcast per-element via `ggml_fp16_to_fp32`.
3. **`D == v->ne[0]` shape SIGABRT.** The playbook's tensor-layout table
   was wrong. `llama_kv_cache::get_k` returns `[D, n_head_kv, n_kv]` —
   not `[D, n_kv, n_head_kv]`. And `v_trans = !cparams.flash_attn` is
   *true* on our path, so V is transposed to `[n_kv, n_head_kv, D]`.
   **Fix:** stride-aware (`nb[]`) reads, derive shape from the correct
   dims, detect v_trans from `v->nb[1] > v->nb[2]`.
4. **`__cxa_throw` from `TurboQuantKVCache::append` SIGILL.** Multi-
   threaded data shuffle in the ggml op partitioned BH per worker, so
   thread 0 prefilled the cache with heads `[0..8)` and thread 1 then
   tried to append heads `[8..16)` — cache class threw on the BH
   mismatch, exception escaped the noexcept ggml callback → terminate.
   **Fix:** session-cached path (`ud->session != NULL`) runs single-
   threaded (`ith=0` does the full BH; other workers no-op). Stateless
   path keeps the multi-threaded shuffle.
5. **`quantize_values: bits must be 2, 4, or 8` SIGABRT** on first
   chat with `value_bits=3`. The value quantizer doesn't support 3-bit.
   **Fix:** revert `value_bits` to 2; bump only `key_bits` to 4.
6. **`TurboQuantKVCache::append() not yet implemented` `std::logic_error`.**
   When kvType=3 was tested with PR #25's session cache, the second decode
   call hit append() which threw. Caught it via the post-merge fix: PR #27
   implements append() with buffer-grow. (PR #25's session cache had a
   safe "drop + re-prefill" fallback, which kept things from crashing
   but cost O(n_kv) per decode token instead of O(1).)

## Backend priority is NEON-first today

`cpp/src/backend_factory.cpp::create_best_backend()` priority:

```
QnnHtp > CpuNeon > OpenCL > Vulkan > CpuScalar
```

NEON is *intentionally* ahead of OpenCL/Vulkan. The host bench
(`cpp/bench/results/`) shows OpenCL is upload-bound at ~17-23 ms per
attention call (per-call `CL_MEM_COPY_HOST_PTR` re-uploads Pi,
quantized K, centroids), while NEON is ~2 ms. Until the OpenCL backend
ships `prepare_keys()` (cl_mem pool keyed by session+layer, K-side
state stays on GPU across decode steps), NEON beats OpenCL end-to-end.

Re-order this list once `prepare_keys()` lands. **It's the comment in
the file** so you can't miss it.

## Why decode is slow

Three layers each contribute to the ~1-2 s/token decode cost:

1. **Per-layer ggml custom op runs on CPU.** `GGML_OP_CUSTOM` is CPU-only
   in ggml-opencl (`ggml/src/ggml-opencl/ggml-opencl.cpp` —
   `supports_op()` defaults to false; no case for `GGML_OP_CUSTOM`).
   Every layer × every token does GPU→CPU sync of Q/K/V, our op runs
   on CPU, result goes CPU→GPU. **16 round trips per token.**
2. **Buffer-portion attention is scalar C++.** `TurboQuantKVCache::
   attention_scores` (kv_cache.cpp:197-214) walks the buffer with
   `double s = 0; for k... s += qv[k]*kv[k]` — no NEON. ~143K
   double-precision scalar FMAs per token across all layers/BH.
   Vectorizing this with `vfmaq_f64` is half-day work.
3. **Single-thread session-cached path.** The custom op runs ith=0-only
   when session caching is active (Fix #4 above). We lose the 4× CPU
   parallelism on the data shuffle. Worth it — the session cache saves
   way more work than 4× threading would.

Two viable speedups, in order of payoff:

- **NEON-vectorize `attention_scores` and `attend` buffer paths.**
  Half-day. ~4× on the buffer dot product, biggest single decode win.
- **Phase A2 GPU persistence — `IBackend::prepare_keys()` + cl_mem pool.**
  Multi-day. Flips the priority back to OpenCL-first and unlocks the
  Adreno path. Bigger ceiling but bigger investment.
